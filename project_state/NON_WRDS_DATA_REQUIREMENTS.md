## Executive Summary

This document maps the project data surface that is not directly sourced from
WRDS. The WRDS source universe is covered separately in
`project_state/WRDS_DATA_REQUIREMENTS.md`; this file focuses on repo-local
artifacts, public/free sources, platform/account exports, private vendor
sources, and derived datasets that must be built or preserved outside WRDS.

The current non-WRDS blockers are not mainly third-party market feeds. They are
the artifacts that preserve project truth:

- local registries and hashes for the current input files;
- curated T-010/T-012 evidence under `docs/artifacts/`;
- local-only recovery bundles and full artifact trees under
  `/Volumes/Storage/Projects/fjs/_recovery/`;
- run logs, configs, manifests, and review bundles that prove what was run;
- synthetic calibration artifacts under `calibration/` and `reports/synthetic/`.

For future expansion, the highest-value non-WRDS additions are public factor and
macro/rate/regime feeds, public SEC/EDGAR metadata, public CBOE/VIX-style stress
series, official exchange calendars, optional ETF benchmark panels, and then
licensed/private vendors only when the research question justifies the data
policy cost. Sharadar/Nasdaq Data Link is already represented in code, but it is
not the canonical current source.

Current answer for the admin/user: yes, enough non-WRDS local artifact context
exists to preserve and understand the current project state, but no, the project
does not yet have a complete optimal non-WRDS research vault. The missing
optimal pieces are mostly source manifests, account/platform archives, and
explicit user decisions about paid/vendor/public feeds.
